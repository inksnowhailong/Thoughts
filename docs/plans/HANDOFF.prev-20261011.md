## 3. 协作约定（新会话务必沿用）

- **远程命令踩过的坑**：
  - 中文版 `findstr` 按 GBK 读 UTF-8，含中文的文件一律用 `Select-String -Encoding UTF8` 核对；`findstr` 参数不要带引号，多个词各用 `/c:`。
  - 复杂命令用 PowerShell `-EncodedCommand`（UTF-16LE base64）。
  - 本机包装会给 `git commit` 插入 `Co-authored-by`，`<` 会被 PowerShell 当重定向；提交命令在本地拼好再交给远程，提交信息只用 ASCII。
  - 停网关要 `openclaw gateway stop --force`；计划任务可能自己把网关拉起来，要确认网关进程启动时间晚于同步和授权。

  - 线上 `levels.json` 必须在网关停下后再同步，回滚时代码和规则文件一起恢复。
  - 语音和托盘必须在桌面会话里跑，用计划任务启动，不能在 ssh 里直接跑。
  - 家里电脑会睡眠导致 Tailscale 掉线；子任务约定掉线每分钟重试最多 5 次。
  - 某个子任务上下文里攒了大量攻击用例后再让它放宽权限，被 Anthropic 安全过滤拦过；这类任务用新开的子任务、按普通产品需求描述。

## 9. 调研结论

### 9.1 初代 Thoughts（报告：`plans\2026-10-10-thoughts-gen1-report.md`）

- **初代是什么**：寄生在 AI 编程工具里的主动陪伴人格，不是独立程序。现行版是 Claude Code 插件（3 个 skill + 2 个 hook + 零依赖 Node runtime），Cursor 时代另有背景子 agent 做「潜意识」。会主动开口、带心情说话，后台把主人原话熔成散文体画像。经历过三种形态：Cursor 版「烤色」（结构化分层记忆）、常驻进程版（已砍）、现在的定时任务 + 热度闸门版（人格「大师」「大痔」）。
- **要传的是机制和理念，不是代码。** 初代的坑不要继承：潜意识整理 9/14 起停摆（会话内定时任务关掉宿主就失效）；心情值卡上限（衰减必须是确定性代码）；状态文件多处读写不加锁；长度上限只写在提示词里没代码校验。
- **最值得移植的前 5 项**：
  1. 潜意识整理铁律写进 P4 休眠整理提示词（只信原话、被推翻就删、原地重写不留变更记录、超限就提炼、同类合并，加「悬着没解的问题」字段；上限由休眠校验步骤用代码检查）。高优先，约半天。
  2. SOUL.md 用散文人格 + 「语料区」 + 底线（不念自己的性格形容词、不汇报运行机制；语料改写成语音短句，休眠时用二代真实说过的话逐步替换）。高，0.5–1 天。
  3. 一次性导入主人画像：复用 P4 整理流程，把「大师」画像和「烤色」高优先记忆蒸馏成 USER.md 主人分节的指令，先进暂存区，主人在面板逐条确认后提交。高，约 1 天 + 主人审阅。
  4. 面板提示词与参数页：提示词抽成带占位符的模板文件，面板显示按当前状态渲染的预览；参数显示默认值与覆盖值，标出何时生效（立即 / 下次休眠 / 需重启）。中高，2–3 天。
  5. 面板记忆页 + 热度闸门：每条记忆带出处可点开看原话，编辑与休眠提交抢同一把锁；初代「什么时候主动说」的零 token 算法做成二代定时检查，主动消息默认走微信，静默时段可多段（深夜 + 午休），打游戏不打扰。中，P5 之后。
- **隐私与体积风险**：「大师」画像 16.8KB，含收入、储蓄、家庭、职场等私密内容；二代 USER.md / MEMORY.md 家人会话也能读到，且有字符上限，所以只能蒸馏后逐条过隐私筛再导入。
- **血缘建议**：
  - 命名先只改显示名（托盘、面板、快捷方式、文档），路径、计划任务名、插件名先别动。人格名可继承初代或新起，SOUL.md 开头写一句「我是从思绪里长出来的」。
  - **唤醒词不要用「思绪」**：读音容错会把它和「时序」当成同一个词，容易误唤醒；保留「管家」。
  - 人设：不变的是底线（不灌鸡汤、不自报设定、不汇报机制、像人一样上线下线、不一味夸）；角色从导师/损友变成全家的管家，回答不超过两句，对家人更温和。
  - 数据：初代数据在**本机**（公司电脑），不在家里那台。真实画像在 `C:\Users\moxue\.thoughts\instances\大师\`，另有 `大痔`，以及项目里旧的「烤色」。只导入蒸馏后的指令；活动日志、心情值、话题线索不导入。
  - 界面：初代颜文字「滴答脸」移到托盘和面板状态卡（表情 · 心情标签 · 近况一句），项目里未实现的 HUD 设计稿可当草图。

### 9.2 声纹诊断（报告：`plans\2026-10-10-speaker-diagnosis.md`）

- **现状**：CAM++（sherpa-onnx，192 维），整句 VAD 片段经 3 倍增益直接打分，与库里唯一的「我」向量算余弦。门槛目前被主人在面板调到 0.20（默认 0.45）。判定顺序是先声纹再唤醒词，所以带「管家」的话也会先被声纹硬拒。
- **分数**：09-30 刚注册（AEC 开）主人中位 0.60；10-01（AEC 关）0.47；今天 0.33。门槛 0.45 时今晚 6 次唤醒全被拒，39 句有内容的话被拦 32 句。主人喊「管家」只有 0.32–0.39，背景声和语气词最高 0.49、0.53，**现在主人和非主人分不开**，设什么门槛都不对。（无人工标注，「主人」按喊了唤醒词近似，14 句样本。）
- **根因（按影响排序）**：
  1. 注册与使用链路不一致：AEC 关了以后一直没重录（主因；3 倍增益影响很小）。
  2. `enroll()` 有 bug：每加一段就把「旧+新」重新归一化，最后一段占一半权重，两轮 24 秒注册实际只由最后两三段决定。
  3. 片段太短：单独一句「管家」只有 0.5–1 秒，又被音箱 DSP 噪声门截掉一部分（0.5 秒 0.26、1 秒 0.34、1.5 秒以上约 0.40）。
  4. 门禁顺序：最短最难认的句子要过最严的门。
- **离线重算**：参照换成同晚没过 AEC 的 5 秒主人录音，主人平均分 0.37→0.51、其他 0.27→0.32，差距翻倍；ERes2NetV2 整体抬高约 0.1 但区分度不比 CAM++ 好，继续用 CAM++；单纯去掉噪声门的零值反而降分。
- **推荐**：
  - **先定角色**：声纹改成「软门禁 + 身份标签」——带唤醒词的话不再因声纹被拒；声纹只在免喊窗口（没喊唤醒词的后续话）当门槛，平时标「主人/家人」，以后做权限分级（区分家人需先给家人注册）。改 `decide()` 十几行，当天可做。
  - **A 面板引导重新注册**（主要收益，约 1–1.5 天）：守护进程进「注册模式」，用日常同一条链路录 8–12 段、每段 3–5 秒，覆盖近处、2–3 米外、带情绪/大声；修 `enroll()`，每段向量都存、打分取平均；质量检查（去零后有效语音至少 1.5 秒）；旧库备份可回滚。预期主人分数 +0.10–0.15。
  - **B 自适应更新**（A 之后，0.5–1 天）：只收带唤醒词、高分、有效语音至少 1.5 秒、没在播 TTS 的话；注册样本作「锚」永不自动修改，新样本进单独池（上限 30）且须对锚达标，每天限量，面板可试听/删除/回滚。
  - **C 校准**（有数据后）：「管家」和紧跟指令合并打分 + 按句长分档门槛（不到 1 秒只标「不确定」不拦）；用积累的非主人片段做 AS-norm。不建议优先做多模型融合。
  - 顺序：当天软门禁 → 本周 A → 之后 B → C 按需。另有小问题：注释过时、默认门槛两处各写一个、`enroll()` 每段写一次盘。

## 12. 排查管家问题（给 AI 的指南；日志系统 B1–B4/B6，2026-10-11）

> **排查管家问题：先查日志，不要先猜代码。** 远程统一这样跑（结果是 UTF-8 文件，不会被 cmd 的 GBK 弄乱）：
> `ssh -o BatchMode=yes home "F:\coding\guanjia\scripts\logq.cmd <参数>"`（屏幕只回一行 `written …`）→ `scp home:F:/coding/guanjia/tmp/logq-out.txt $env:TEMP\logq.txt` → 用 Read 读。关键字带中文用 `--kb64 <base64(UTF-8)>`（PowerShell：`[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('音响'))`），不要直接在 ssh 命令行里写中文。

**数据在哪**：`F:\coding\guanjia\tmp\logs\events-<进程>-<日期>.jsonl`（语音进程 `events-voice-*`；一事件一行 `{ts, comp, level, ev, uid?, msg?, data?}`，UTF-8）；大字段（发给模型的上下文）在 `tmp\logs\blobs\<日期>\<uid>-gwctx.txt`。保留：事件 14 天、blob 7 天、blob 总量 300MB，到期自动清。旧的 `voice.log`、`utterances.jsonl` 原样保留。`GUANJIA_ELOG_LEVEL=debug` 才会落盘 debug 事件（默认 info 及以上）。

**步骤**
1. **先定位这一轮**：主人说「刚才」→ `--recent 15`；说了时间 → `--recent 15 --since "13:30" --until "13:50"`；主人在面板点过「这句有问题」→ 先 `--flags`（默认看 1 天，`--since 7d` 看一周）。每行形如 `13:48:07.3 [u134807-012] mic/accept 「…」→「…」 model=DeepSeek-V4-Flash stop=stop tools=0 首音=2300ms`，`[]` 里就是 uid。默认只列 accept/wake_only/say/追问轮，`--all` 连被拒的、被忽略的也列。
2. **看一轮**：`--turn <uid>`。依次是：相对毫秒的时间线（听→识别→声纹→唤醒→网关→工具→合成→播放）、回复/念出/漏念、**网关段**（模型、stop、token 入/出/缓存、每次工具调用 ✓/✗ 与耗时/参数/错误、模型原文、本轮时间窗内网关日志的 WARN 与本 run 行）、末尾 `!!` **诊断行**（例如「模型说了要做但一次工具调用都没发就 stop 了」=模型行为问题不是工具被拦；「回复声称被拦/要审批但没有任何拦截记录」=模型编造；工具失败；非正常 stop；漏念）。被自动追问的那一轮会提示 `追问轮：--turn <child>`，接着看 child。`--detail` 展开 data（输出会变大）。
3. **按模块深挖**（`--since` 默认 2 小时，加了 `--boot/--recent/--flags` 才是 1 天）：声纹录不上 `--ev "enroll.*" --since 30m`（每段一行：有效语音秒数、零值占比、峰值、是否和播放重叠、与已收样本的相似度）；没声音 `--comp tts,play --level warn --since 1h`；工具/审批 `--comp tool --since 1h`（`tool.audit` / `tool.gate` / `pending.open|close`）；追问 `--comp nudge --since 1h`（`nudge.check` 每次判定与原因，`nudge.sent` 有 parent/child）；启动/重启/依赖 `--boot`（`voice.start|ready|exit`、`dep.change` 依赖变化、同期 WARN 以上）；任何异常 `--level error --since 1d`；面板改设置/控制 `--comp panel`。
4. **要看模型到底收到了什么**（输出很大，最后才看）：`--payload <uid>`（优先读 blob；没有再现查网关 trajectory，网关那边只留约 10MiB 滚动窗口，旧的可能已没了）。
5. **旧文本日志**（新事件里没有的老问题）：`--tail voice -k <英文关键字>`、`--tail stderr`、`--tail tts`、`--tail sup`（已滤掉每 10 秒一行的健康检查）。
6. **不经语音的轮次**（微信/TUI）：`--runs 10`，直接读网关 trajectory，一行一个 run，标出能对上的语音 uid（对不上是 `-`；渠道一栏语音轮也显示 webchat，是网关接口的叫法）。
7. **兜底才用 OpenClaw 自带**：`openclaw logs --json --limit 200`（网关日志）、`openclaw sessions export-trajectory --session-key agent:main:main --json`（整会话导出，很大）。

**参数速查**：`--recent N [--all]` `--turn UID` `--flags` `--runs N` `--payload UID|RUN_ID` `--boot` `--tail voice|stderr|tts|sup`；筛选 `--since 10m|2h|1d|"13:40"|"2026-10-11 13:40"` `--until` `--uid` `--comp a,b` `--level info|warn|error`（最低级别）`--ev "enroll.*,tool.*"` `-k 关键字` `--kb64`；输出 `--detail` `--json` `--max-lines 80` `--max-chars 8000` `--out 文件`（`logq.cmd` 已固定写 `tmp\logq-out.txt`）；测试/迁移 `--log-dir --legacy-file --agent-db --gw-log-dir`。

**规矩**：默认输出已截断（行数/字数有上限，超出会提示「还有 N 行没显示」），确实需要才加 `--detail`、调大 `--max-lines/--max-chars`；`--turn` 的诊断行不受上限约束。logq 全程只读（读事件文件、旧记录、网关 sqlite 用 `mode=ro`），不会锁网关。事件里不含令牌（统一脱敏：Bearer、`sk-…`、`token/key/secret/password=…`）；blob 含对话正文，仅存本机。
