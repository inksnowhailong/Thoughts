# 思绪二代 · 记忆重新设计（2026-10-13，Opus）

> 主人原话：「我们的记忆不应该是全堆过去的，而应该是有一定分层和索引的。首先内容量可放宽，其次我们对记忆要做个重新设计。」另：智力比速度重要；初代画像全部放开；人格叫「大痔」。
> 本文是设计。实现批次见 `2026-10-13-p4-plan.md`（已按本文修订）。执行者开工前读本文第 1–6 节。

---

## 0. 一句话

**常驻的只放「现在用得上的」，其余按人 / 主题 / 时间分文件放进可检索的长期层，中间用一张自动生成的目录告诉模型「还有哪些可以查」；休眠负责在层与层之间升降，每条记忆都带出处，能点回原话。**

```
            ┌─────────────── 每轮常驻（主线；家人会话按面板开关）────────────────┐
  L0 人设    │ SOUL.md（大痔）· IDENTITY.md · AGENTS.md 规矩                      │ ≈2.8k token
  L1 核心    │ USER.md：主人画像与偏好 / 通用 / 每位家人                         │
            │ MEMORY.md：关键事实 · 悬而未决 · 最近要点                         │ ≈5.1k token
  L2 索引    │ MEMORY.md「记忆目录」：有哪些人物档案、主题、日记可查（自动生成）  │ ≈0.8k token
            └──────────────────────────────────────────────────────────────────────┘
                 ▲ 升（重要/常被用到）        │ 降（超预算/久不用）
                 │                            ▼
            ┌─────────────── 按需检索（memory_search / memory_get / 预取）──────────┐
  L3 长期    │ memory/people/<人>.md   人物档案（事实、偏好细节、关系、洞察）       │
            │ memory/topics/<主题>.md 主题事实（家里设备、健康、财务、工作、饮食…）│
            │ memory/YYYY-MM-DD.md    情景/日记（每段对话一节，OpenClaw 原生）     │
            │ memory/timeline.md      时间线（一行一事件，只追加）                 │
            │ memory/index.md         完整目录（L2 的全量版，不注入）              │
            ├──────────────────────────────────────────────────────────────────────┤
  L4 原文    │ OpenClaw SQLite 转写（全部原话，只读）：sessions_search / sessions_history │
            └──────────────────────────────────────────────────────────────────────┘
```

## 1. 分层总表

| 层 | 文件 / 位置 | 内容 | 预算（字符，代码校验） | 谁写 | 谁读 | 方式 |
|---|---|---|---|---|---|---|
| L0 人设 | `SOUL.md`、`IDENTITY.md`、`AGENTS.md` | 大痔人设（散文 + 底线 + 语料）、名字称呼、做事规矩 | SOUL ≤1,500；IDENTITY ≤150；AGENTS ≤2,500 | 主人面板；休眠只换 SOUL 语料（开关，默认关） | OpenClaw 每轮注入 | 常驻 |
| L1 核心 · 画像 | `USER.md` | 主人：2–3 行散文「他是谁」+ 偏好/雷区指令；通用规则；每位家人的关键偏好 | 全文 ≤4,000；主人 ≤2,400；通用 ≤400；每位家人 ≤600 | 对话中模型（主人说「记住」）；休眠；面板 | 每轮注入（主线 + 家人会话） | 常驻 |
| L1 核心 · 记忆 | `MEMORY.md` 三节 | 关键事实（家庭与家里）；悬而未决（≤8 条）；最近要点（最近 3 段的交接） | 关键事实 ≤900；悬而未决 ≤700；最近要点 ≤1,600 | 休眠（整节重写）；面板 | 每轮注入（主线；家人会话见第 7 节） | 常驻 |
| L2 索引 | `MEMORY.md`「记忆目录」节 | 每个长期文件一行：路径、一句话摘要、条数、最近更新；人物与主题关键词 | ≤1,200 | **只由代码生成**（休眠提交后重建），面板只读 | 每轮注入 | 常驻 |
| L3 长期 · 人物 | `memory/people/<称呼>.md` | 这个人的事实、偏好细节、关系、经历、洞察（反思） | 每文件 ≤6,000，超了提炼或拆分 | 对话中模型（追加）；休眠（增删改、洞察）；面板 | `memory_search`/`memory_get`；预取 | 检索 |
| L3 长期 · 主题 | `memory/topics/<主题>.md` | 家里设备、健康、财务、工作、饮食、出行、孩子教育……按需新建 | 每文件 ≤6,000 | 同上 | 同上 | 检索 |
| L3 长期 · 情景 | `memory/YYYY-MM-DD.md` | 每段对话一节：发生了什么、决定、承诺、未结（OpenClaw 原生每日笔记，30 天新近度衰减） | ≤12,000/天 | 休眠追加；对话中模型可追加 | 同上；换新后首轮 OpenClaw 可能前置最近几天（E6 量） | 检索 |
| L3 长期 · 时间线 | `memory/timeline.md` | `日期 时刻 \| 谁 \| 类别 \| 内容 \| src` | 不设上限，按月滚动（>30KB 时休眠把旧月搬到 `memory/timeline/YYYY-MM.md`） | 对话中模型（记事技能）；休眠 | 同上 | 检索 |
| L3 长期 · 全目录 | `memory/index.md` | L2 的全量版：每个文件的每个小节标题与条目数 | ≤8,000 | 代码生成 | 检索 | 检索 |
| L4 原文 | OpenClaw SQLite `transcript_events` | 全部对话原文 | — | OpenClaw | `sessions_search`/`sessions_history`；休眠导出；面板「出处」 | 检索（只读） |
| 暂存 | `data/sleep/staging/`（仓库，工作区外） | 演练产物、初代导入候选 | — | 休眠、导入脚本 | 面板确认页 | 不注入 |

> `guanjia/family-facts.json` 不属于记忆：它是脱敏代理的实体名单（人名 → 占位符），只许追加。休眠在新建 `memory/people/<称呼>.md` 时把称呼追加进去（老婆的名字按主人决定加入）。

## 2. 条目格式与出处

**一行一条，行尾注释带元数据**（长期层、MEMORY 关键事实、悬而未决都用这种）：

```markdown
- 老婆对花生过敏，做菜避开。 <!-- id: p12 | src: s:cd9359fe#266 | t: 2026-10-13 | imp: 8 | hits: 3 | lh: 2026-10-20 -->
```

| 字段 | 含义 |
|---|---|
| `id` | 文件内唯一；前缀 `u`（USER）`k`（关键事实）`o`（悬而未决）`p`（人物）`t`（主题） |
| `src` | 出处：`s:<sessionId 前 8 位>#<seq>` 转写某条消息；`d:<摘要 id>` 家人摘要；`gen1:<实例>/<文件>` 初代导入；`panel` 主人在面板手写；`chat` 对话中模型写的（休眠下次会按证据回填成 `s:`） |
| `t` | 首次记录日期 |
| `imp` | 重要度 1–10（休眠打分，沿用初代「≥4 才影响画像」） |
| `hits` / `lh` | 被用到的次数 / 最近一次（休眠按本段导出里被提到、或语音预取命中记账） |

**USER.md 沿用 OpenClaw 约定**（注释在指令前一行），字段同上：

```markdown
<!-- observed: 2026-10-13 | status: active | id: u3 | src: s:cd9359fe#266 | imp: 9 -->
- Never 深夜 23:30 后主动出声，只发微信。
```

**文件头**（长期层每个文件前三行，供目录与预取使用；由休眠维护，模型和面板也能改）：

```markdown
# 老婆
> 摘要：主人的老婆，过敏与作息信息在这里；最近在准备换工作。
> 关键词：老婆、媳妇、<名字>、ef79
```

**出处可点开**：面板读 `src: s:…#seq` → 只读查 SQLite 那条消息及前后各 2 条，弹窗显示原话（见第 8 节）。

## 3. 检索：复用 OpenClaw，补一个零成本预取

### 3.1 OpenClaw 自带的（已核实，`docs/concepts/memory*.md`、`docs/reference/memory-config.md`）

- 工具：`memory_search`（语义 + BM25 关键词 + 文件名混合检索；排序 = 相关度 × 新近度衰减 × 重要度；日记 30 天半衰期，`MEMORY.md`/`USER.md` 与 `memory/` 下**不带日期的文件长期有效**；默认 `maxResults 6`、`minScore 0.35`；交互调用最多 3 次尝试、8 秒）与 `memory_get`（按路径/行号读）。原文检索用 `sessions_search` + `sessions_history`。
- 现配置：`memory.search.provider = openai`，模型 `Qwen/Qwen3-Embedding-0.6B`，走硅基；`sources` 默认 `["memory"]`。线上索引现在只有 `USER.md`、`memory/timeline.md` 两个源（`memory_index_sources` 实测），说明默认根是 `MEMORY.md`、`USER.md`、`memory/`；子目录是否递归要实测（文档里 `memory/imports/...` 被索引，推断递归）——**P4-1b 验证**，不递归就把 `memory/people`、`memory/topics` 加进 `memory.search.extraPaths`。
- 「确定性触发召回」只会自动注入根 `MEMORY.md`/`USER.md` 里带触发词的条目——这两个文件本来就常驻，对我们没增益，不依赖它。
- Active Memory（`escalate` 模式：问到过去且触发召回没命中时，跑一个阻塞的召回子代理）：要多一次模型调用（文档建议超时 3–5 s），**语音默认不开**；P4-6 演练期做一次对比实验，再决定是否只给微信轮开。
- **关键现状**：`memory_search`/`memory_get` 现在藏在 tool search 后面（主线直接可见的 16 个工具里没有它们），模型要先 `tool_search` 才能查记忆——这和「光说不做」同源。所以 P4-1b 改成 `tools.toolSearch: false` + 工具白名单，让记忆工具直接可见。
- 可选：`sources` 加 `"sessions"`，让 `memory_search` 也能语义召回旧对话原文。默认先不开（索引要重建、家人会话也会被索引）；P4-9 稳定后再评估。

### 3.2 我们补的：名字 / 主题触发预取（guard 插件，零模型调用）

- 时机：`before_prompt_build`，只在人发的话（语音轮、微信轮）上做。
- 做法：从 `memory/people/*.md`、`memory/topics/*.md` 的文件头读「关键词」（按修改时间缓存）；本轮原话（去掉语音标记）命中关键词 → 取该文件的摘要行 + `imp` 最高的 ≤6 条，作为 `appendContext`：`[相关记忆·老婆] …`。最多 2 个文件、≤800 字。
- 记账：把预取到的条目 id 写进 `workspace/guanjia/prefetch.jsonl`，休眠据此加 `hits`。
- 延迟：读本地小文件 + 字符串匹配，目标 ≤20 ms，不进首字关键路径的可感知范围。
- 为什么不是向量预取：每轮都要调一次远端 embedding（约 0.2–0.5 s，硅基），而「提到人/主题」的场景关键词就够了；语义查询交给模型自己调 `memory_search`。

### 3.3 模型什么时候查（写进 AGENTS 规矩）

- 问到过去的事、某个人或某个主题的细节，目录里有对应文件，或预取里没有答案 → 先 `memory_search`（必要时 `memory_get` 读整节）；查原话用 `sessions_search`。
- 要替某人做事（买东西、订提醒、发消息）前，先看这个人的档案。
- 查不到就说不记得，不编。
- 语音轮最多查一次（每次检索 = 多一轮模型往返，约 1.5–3 s）。

**延迟预算**：语音轮常规 0 次检索、只有预取（≤20 ms）；涉及过去的语音轮允许 1 次检索，端到端额外 ≤3 s；微信轮不限次数（工具轮上限照旧）。`memory_search` 工具本身耗时目标 p50 ≤1 s（P4-1b 实测）。

## 4. 休眠在各层上怎么工作

### 4.1 输入

本段对话导出（检查点之后）+ 家人摘要（P3）+ 全部核心层 + 目录 + **只挑相关的长期文件**（用和预取一样的关键词匹配本段原话，选中的文件全文，合计 ≤12,000 字；没命中的不送，避免把整库喂给模型）。

### 4.2 初代铁律落在哪一层

| 铁律 | 作用层 | 代码怎么保证 |
|---|---|---|
| 只信原话 | 所有写入（L1、L3） | 每条 add/rewrite 必须带 `evidence`，是主人/家人原话（或家人摘要）的逐字子串，否则丢弃；`src` 由代码按证据所在消息填 `s:<sid>#<seq>`，模型不能自己编出处 |
| 被推翻就删 | L1、L3 | rewrite（保 id）或 delete；没有「以前…现在…」；旧版只在面板历史里 |
| 原地重写 | L1、L3 人物/主题 | 条目按 id 原地替换；**情景（日记）、时间线、原文不重写**，它们是记录 |
| 超限就提炼 | L1 每节、L3 每文件 | 渲染后校验长度；超了先让模型提炼重写一次；仍超就**按规则降层**（见 4.3），不是硬截断 |
| 同类合并 | L1 指令、L3 人物/主题 | 提示词要求合并；代码查「同一节内去标点后完全相同或包含关系」的条目，自动并成一条 |
| 悬而未决 | L1「悬而未决」 | 新提出未解决的 → 加；有原话证明解决了 → 删；14 天未动 → 降到当天日记「未结」小节 |
| 短期 ≠ 长期 | L1「最近要点」 vs USER | 「最近不想…」进最近要点（随段滚动消失），不写成 USER 指令 |
| 反思（借生成式智能体） | L3 人物「洞察」小节 | 每段最多 2 条，每条至少 2 处证据；只进长期层，**不自动升核心**，主人在面板手动升 |

### 4.3 升降规则（确定性代码，模型只建议）

**升到核心**（L3 → L1，满足其一，且升完不超预算）：
- `imp ≥ 8` 且是主人的长期偏好/雷区（Always/Never/Prefer）→ USER.md 主人分节；
- 14 天内被 ≥2 个不同段用到（`hits` 增量 ≥2）；
- 主人在面板点「升到核心」。

**降到长期**（L1 → L3，原地删 + 在对应人物/主题文件追加同 id 的条目，带原 `src`）：
- 某节超预算：按 `(imp 升序, lh 升序)` 依次降，直到达标；
- 关键事实 60 天未被用到且 `imp < 7`；
- 悬而未决 14 天未动；
- 最近要点只保留最近 3 段，更早的自然删除（它们在当天日记里有完整版）。

降层永远不删内容；删除只发生在「被原话推翻」或主人在面板删。

### 4.4 输出 JSON（模型）→ 代码

```json
{
  "segment": {"title": "晚饭后聊换工作和周末安排", "events": [], "decisions": [], "promises": [], "unresolved": []},
  "recent": "本段要点，≤500 字（进 MEMORY 最近要点）",
  "openLoops": [{"op": "add|close", "id": "o3（close 时）", "text": "…", "evidence": "…"}],
  "ops": [{"op": "add|rewrite|delete", "file": "core.user.主人 | core.user.<家人> | core.user.通用 | core.facts | people/<称呼> | topics/<主题>",
           "id": "…（add 省略）", "text": "一行", "evidence": "逐字原话", "imp": 1-10}],
  "insights": [{"person": "主人", "text": "…", "evidence": ["…", "…"]}],
  "headers": [{"file": "people/老婆", "summary": "一句话", "keywords": ["…"]}],
  "used": ["p12", "t4"],
  "timeline": [{"t": "YYYY-MM-DD HH:MM", "who": "主人", "kind": "决定|承诺|到访|采购|维修|变更", "text": "…"}],
  "soulCorpus": null
}
```

代码依次做：证据校验与填 `src` → 同类合并 → 应用 ops → 升降 → 渲染最近要点（滚动 3 段）→ 记 `hits` → 重建目录与 `memory/index.md` → 长度校验 → 删除比例校验 → 原子提交。

### 4.5 目录怎么生成（代码，不调模型）

```
## 记忆目录（自动生成，可用 memory_search 查，或 memory_get 读整份）
- 人物：老婆（23 条，10-20）· 主人（41 条，10-19）· 妈妈（6 条，10-02）
- 主题：家里设备（18）· 健康（9）· 工作（15）· 财务（7）· 饮食（5）
- 日记：10-01 至 10-20 共 14 天 · 时间线 212 行
- 最近新增：老婆换工作（10-20）、空调滤网（10-18）
```

超过 1,200 字时只列条目最多、最近更新的，末尾写「其余见 memory/index.md」。

## 5. 上下文预算（放宽后）

| 项 | 预算 | 约 token |
|---|---|---|
| OpenClaw 自带段落（不可配） | — | 4.9k |
| 工具（关掉 tool search 后，白名单约 20 个直接给 schema） | P4-1b 实测 | ≈5k |
| 技能列表（4 个） | — | 0.3k |
| L0 人设 + 规矩 | SOUL 1,500 + IDENTITY 150 + AGENTS 2,500 | 2.8k |
| L1 核心 | USER 4,000 + MEMORY 三节 3,200 | 5.1k |
| L2 目录 | 1,200 | 0.8k |
| 预取 | ≤800 | ≤0.6k |
| **固定开销合计（新会话一句话）** | | **≈19.5k，目标 ≤20k，告警线 22k** |
| 本段对话（休眠控制） | 平均 ≤25k | |
| **典型单轮 prompt** | | **≤45k；峰值 60k 触发强制休眠** |

理由：
1. 智力优先——核心记忆从 v2 的「≤11k 固定开销」放宽到约 5k 记忆 token，关键画像与家庭事实常驻，不靠模型想起来去查。
2. 工具直接可见多花约 2–3k，但换掉「先 tool_search 再调」的绕路（每次 +1.5–2.5 s，且是光说不做的主因），对智力和速度都是净收益。
3. 仍要砍的「无用堆积」不变：25 个技能 → 4 个（−1.8k）、AGENTS 英文默认段（−1.4k）、心跳（打断缓存）、用不到的工具（`openclaw`、`sessions_yield`、`apply_patch`）。
4. 128k 窗口、连续轮缓存命中约 95%：固定开销多出的部分基本按缓存价计费；首字代价约 +0.3–0.5 s（冷启动轮），主人已明确接受。

## 6. 和业界的关系（一句话）

借了 **MemGPT/Letta** 的「带字数上限的常驻核心块 + 可检索的归档/回忆层」，没借它「模型每轮自己调函数换页」——我们的整理放在休眠里离线做，对话轮不付这个延迟；借了 **生成式智能体（Generative Agents）** 的「相关度 × 新近度 × 重要度」检索（OpenClaw 已内建）和「反思」（休眠写洞察），没借它「每条观察实时让模型打重要度」——重要度只在休眠时打一次。

- 主人决定：家人与主线同权、画像全部放开；但要提供收紧开关，**默认不收紧**。
