# 思绪本机面板 Workbench 实施设计稿

> **For agentic workers:** 实施本稿时使用 `executing-plans`；遵循项目 Git 规则，未获主人要求不得建分支、worktree、提交或重启服务。任务步骤用 checkbox 跟踪。

**目标：** 把当前“功能集合页”重组为管家工作台，使主人打开页面后三秒内能回答：它是否在听、正在替我做什么、是否等我确认、上一件事结果是什么。

**设计原则：** 首页是“此刻态势”，不是配置目录；一件正在发生的事应从状态、进度、待确认、结果沿同一条叙事连续呈现。详细记录、编辑器与低频配置退到二级视图，避免每种能力各占一张同等权重的卡片。

**边界：**

- 本稿依据 `src/guanjia/panel.py`、`src/guanjia/panel.html`、`docs/plans/WORKER-NOTES.md`、`docs/plans/HANDOFF.md` 与 `tmp/2026-10-14-orchestration-design.md` 的当前事实编写。
- 用户指定的 `docs/plans/2026-10-14-orchestration-design.md` 当前不存在；实际已读副本是 `tmp/2026-10-14-orchestration-design.md`。实施前应把设计稿归档到 `docs/plans/`，但不可假设编排功能已经上线。
- 当前后端快照只提供 `status / settings / records / logs / live / stages`，且现有路由只有面板控制、设置、注入、提示词、记忆、声纹与已记住放行；尚无“待确认”或“任务”数据模型/API。
- O1/O3 接线前不得伪造任务百分比、可取消状态或待确认项；首页应明确显示“暂无待确认 / 暂无进行中任务”，或在功能未接入时隐藏其操作入口。

## 1. 当前页面的真实结构与问题

当前 `panel.html` 是单文件深色页面，数据经 `/api/snapshot` 加载、SSE `/api/events` 增量推送。页面自上而下为：

1. 顶部：状态 pill、网关/TTS/休眠/免喊/唤醒词，以及静音、重启、退出。
2. “一次说话的流程”：当前/最近一句的阶段盒子；可展开参数、提示词、已记住放行的抽屉。
3. 左右两列：最近 50 句记录与单句详情（含工具、耗时、时间线）。
4. 实时日志（模块、级别、关键词筛选）。
5. 声纹注册卡、全量语音设置、模拟一句话。
6. 记忆文件列表与编辑器；`panel_memory.js` 在服务端内联。

### 1.1 主要问题

| 现状 | 为什么妨碍使用 | 重设计决定 |
|---|---|---|
| 顶部状态分散为小字和一个通用 pill | 主人要把“连接中/监听/说话/静音/异常”与网关、TTS、休眠逐个拼起来理解 | 把“耳朵状态”升为首页第一视觉层；依赖健康降为紧凑辅助信息。 |
| 流程图关注“一句话经过哪些阶段” | 它对调试有价值，但不回答“现在正在替我干什么”；也没有长任务、确认、完成结果的位置 | 流程图退到“本轮详情”，首页换成一条“当前事务带”。 |
| “每句话”、日志、声纹、设置、记忆都平铺 | 高频看态势与低频维护抢同一层级，页面长、焦点跳跃，像功能堆叠 | 分成“概览 / 事务 / 记录 / 记忆与设置”四个工作区。 |
| 已记住的放行在“工具”流程节点的抽屉里 | 它与即将引入的一次性确认不是一件事；主人无法一眼判断是否正等自己 | “待确认”成为全局一等区；“已记住的放行”保留在安全/设置二级页。 |
| 最近一句详情包含回复、工具、耗时与时间线，但没有“上一件结果”摘要 | 结果被淹没在表格、展开详情和日志里，刚完成的事不可扫读 | 首页固定“上一件事”条：结果、完成时间、关键证据、进入完整记录入口。 |
| 日志固定占 300px 且筛选多 | 排障能力正确，但默认占据首页注意力；普通使用者只关心异常和当前事务相关事件 | 首页仅显示紧凑活动流（最近 5 条，异常优先）；完整日志进入“记录”。 |
| 静音、重启、退出与日常状态并排 | 高风险运维操作过于靠前，容易与“正在听”混淆 | 顶栏只保留静音；重启/退出收进“运行控制”二级区并保留二次确认。 |

### 1.2 不能从前端自行补齐的事实

- 当前 `records` 描述的是一次语音轮次，不能代表将来独立任务会话的生命周期。
- `live`/`stage` 只有语音阶段状态，不含长任务步骤、任务所有者、进度、取消能力或等待原因。
- 已记住放行（`/api/overrides`）是长期规则清单，不等于 O1 的一次性放行事项。
- 现有 SSE 事件没有 `task` 或 `approval` 类型；在此之前不能做“实时任务列表”。

## 2. 信息架构

```
思绪 Workbench
├─ 概览（默认首页：此刻态势）
│  ├─ 耳朵状态 + 依赖健康
│  ├─ 当前事务（本轮 / 长任务）
│  ├─ 待确认（O1）
│  ├─ 上一件事结果
│  └─ 最近活动（压缩日志）
├─ 事务
│  ├─ 进行中 / 排队 / 等确认 / 已完成（O3）
│  └─ 单任务进度、取消、证据与完整事件
├─ 记录
│  ├─ 对话轮次与本轮流程、工具、耗时
│  └─ 可筛选实时日志与“这句有问题”
└─ 知识与设置
   ├─ 记忆
   ├─ 提示词与流程参数
   ├─ 声纹
   ├─ 已记住的放行
   └─ 运行控制与模拟输入
```

“概览 / 事务 / 记录 / 知识与设置”应是同页锚点或轻量 Tab；不引入路由框架。切换后保留 SSE 连接和当前选择，避免状态闪断。

### 3.1 主界面线框

```text

├──────────────────────────────────────────────────────────────────────────┤
│ 现在在做什么                                                          查看事务 → │
│ ┌─ 本轮 ─────────────────────────────────────────────────────────────────┐ │
```

### 3.2 首页必须优先回答的四个问题

| 问题 | 来源 | 显示规则 |
|---|---|---|
| 现在是否在听？ | 现有 `status.view / label / muted` | 用“耳朵状态”大标题、色点、短句表达；`listening`、`busy`、`muted`、`gaming`、`starting`、`error` 必须有文字，不只靠颜色。 |
| 正在做什么？ | 先用当前 `live` + 最新非 `say` record；O3 后优先活动任务 | 一行动词化摘要（“正在识别/正在回话/正在下载”），附耗时和下一步；没有活动时明确“现在没有替你办的事”。 |
| 是否等我确认？ | O1 的 approval API | 有待确认时占固定位置、琥珀/紫色强调、显示对象/后果/过期时间；无时显示“没有等你确认的事”，不留空白。 |
| 上一件事结果？ | 先由最近已结束语音轮次归纳；O3 后由最近终态任务提供 | 永远显示成功、失败、取消或未证实，绝不把“已开始”写成“已完成”；点击进入证据与全过程。 |

### 3.3 视觉层级

- 主色为低饱和石墨黑/墨绿背景，文本对比优先；成功用柔和绿色、进行中用冷青/蓝、需主人决定用琥珀到紫色、故障用朱红。每种颜色均配文字与图标。
- “听”是常驻、稳定的呼吸点；“正在做”用细进度线/运行时间表示流动，不使用大面积闪烁。只在状态从正常切为“等确认/失败”时一次性强调。
- 不以四个相同圆角卡片拼出首页。首页结构是状态横幅 + 事务叙事带 + 两个不对称的关键栏 + 日志细线，边框仅用于界定可操作或异常对象。

## 4. 各分区交互

### 4.1 事务（O3 后）

- 默认按“等确认 → 进行中 → 排队 → 最近完成”分组；进行中任务占首位，每项显示任务名、当前一句进度、开始/更新时间、所属来源（语音/微信）、状态。
- 点击任务打开右侧或下方详情：目标、步骤活动流、最后一条报告、相关工具证据、确认项、最终结果。不要把原始实时日志直接作为任务摘要。
- `取消` 只在 `queued / running / waiting_approval` 可用；点击后先显示“正在请求停止”，收到终态事件才显示“已取消”。没有 O3 API 时不出现假按钮。
- O5 接入后，任务进度由 `task_report` 更新；无百分比时显示阶段和最后更新时间，不能臆造百分比。

### 4.2 待确认（O1 后）

- 首页只显示最近且需要主人处理的一项；存在多项时显示“另有 N 项”，进入事务/确认抽屉按最新优先处理。
- 详情固定写出：动作、对象、为何需要确认、所属任务（若有）、创建时间、10 分钟有效期、影响范围。
- 按钮文案为“确认执行 / 拒绝”；语音确定性词表仍是主路径，面板按钮是等价的明确操作。点击后立即禁用并显示“正在提交”，直到 SSE/响应确认终态。
- “以后都允许”不是默认按钮。仅当现有守卫明确允许记忆放行且提供可解释规则时，放在详情二级操作中。

### 4.3 记录

- 保留当前“每句话”表、单句详情、阶段流程、耗时条、“这句有问题”、模块/级别/关键词日志筛选；这是工程诊断区，不再挤在概览。
- 点击概览的“看过程”应定位到对应 `uid` 或 `task_id`；若关联对象已过期，明确提示“记录已不在面板缓冲区，使用 logq 查询”，不展示空白详情。
- 日志默认显示当前事务关联的事件和警告；用户主动选择后才进入完整 800 行实时流。

### 4.4 知识与设置

- 记忆、提示词/参数、声纹、已记住的放行、模拟输入、运行控制放在同一低频区，但使用分段导航而不是一页长表单。
- 保留现有编辑冲突、历史、预算、声纹注册与回滚语义；重设计不得削弱这些防误操作能力。
- “重启语音 / 退出语音 / 模拟真的执行”均移到运行控制，保留现有确认弹窗和后端 token 校验。

## 5. 接线依赖：可先改与必须等待

| 能力 | 可先改（当前 API 足够） | 必须等待 |
|---|---|---|
| 耳朵状态、网关/TTS/休眠、免喊 | 是。取 `status`、settings 与 SSE `status`。 | 无。 |

- 保持：`src/guanjia/panel_memory.js` — 不随布局重写；只在其挂载点位置改变时核对记忆编辑器仍可工作。

### 批 P1：一次性确认工作台（等待 O1）

**文件边界：**

- 修改：`src/guanjia/panel.py` — 注册 approval 的 GET/POST 路由，把权威快照与事件映射给页面；不在此层重写放行逻辑。
- 修改：`src/guanjia/panel.html` — 待确认区、详情、乐观禁用、SSE 同步与过期展示。
- 修改：O1 实际定义 approval 的语音/守卫模块（预计 `src/guanjia/voice.py`、`openclaw/plugins/guanjia-guard/` 及其测试）；面板只消费稳定接口。
- 保持：`/api/overrides` 的长期已记住放行功能，归入“知识与设置 > 安全规则”。

**接口契约（由 O1 固化后再编码）：**

```json
{
  "id": "approval-...",
  "status": "pending|approved|rejected|expired",
  "summary": "删除 3 个临时文件",
  "reason": "文件删除需要确认",
  "task_id": "task-... 或 null",
  "created_at": "ISO-8601",
  "expires_at": "ISO-8601"
}
```

面板动作只能是 `approve` / `reject`，必须携带 `id`；服务端负责幂等与过期判定。

## 7. 视觉方向（选一后实施）

### 方向 A：静默值守台（推荐）

像夜间值班台而不是 SaaS 仪表盘：深石墨底、窄横向信息带、少量高对比文字。耳朵状态用一个稳定的色点和简短人话（“正在听”“正替你办事”“等你一句话”），当前事务像一张正在写的便签横贯页面；完成结果像盖章后的简报。

优点是可读性最好，低频配置自然退后，适合家中远看和游戏时瞥一眼。缺点是装饰性较少，需要用文案和微妙状态过渡建立“思绪”的性格。可使用极轻的“滴答”节律（更新时间、短状态符号），但不引入拟物表盘或高频动画。

### 方向 B：管家事务簿

把首页做成一页有层次的事务簿：顶部是“此刻”，中部是“正在办 / 等你一句”，右侧或下方是“刚办完”，底部是一条可展开的活动时间线。视觉以暖灰纸感与墨色文字为基调，异常、确认和进行中只用一笔颜色标记。

它更有人情味，也更贴合“思绪/管家”而不是监控台；但需谨慎控制纹理和阴影，保证暗色环境、长日志和中文小字仍清楚。实现时仍沿用现有离线单文件 CSS，不引入外部字体、图标库或图片资源。

## 8. 实施前后的验收清单

- [ ] 首屏的四个核心答案都能在 3 秒内读出，且每个状态有文字、颜色和时间/上下文。
- [ ] 任何“完成”均有真实终态或既有工具/记录证据；“已开始”“正在处理”“未核实”必须分开。
- [ ] O1/O3 未接入时不伪装能力；接入后通过 snapshot + SSE 实时更新，不轮询堆叠。
- [ ] 现有面板的 token 校验、冲突保护、历史恢复、声纹回滚、控制确认不退化。
- [ ] 在常用桌面宽度与窄窗口下，状态横幅、待确认与当前事务优先于日志和表单。
- [ ] 仅在准备合入生产前执行全量静态检查；日常实现阶段按项目既有最小验证路径进行。

## 9. 决策记录

- 推荐先实施 P0，先解决“看不出现在在干嘛”的核心问题；它不等待编排重构，也不改变任何语音行为。
- O1 的待确认与 O3/O5 的任务状态必须由各自的权威服务提供，面板是工作台，不是第二套状态机。
- 推荐采用“静默值守台”方向：状态感强、远看清楚，也能容纳任务与确认的成长空间，避免模板化卡片墙。
