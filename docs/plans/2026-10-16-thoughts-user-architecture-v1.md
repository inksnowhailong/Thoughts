# 思绪 · 用户主导架构规格 v1

> 日期：2026-10-16  
> 状态：六个顶层模块的第一版边界已锁定  
> 性质：架构规格，不代表当前代码已经实现  
> 配套 Canvas：`thoughts-user-architecture.canvas.tsx`

## 1. 目标

思绪采用传统模块化、低耦合架构。模块只通过明确的数据契约和事件通信，不直接读取其它模块的内部状态或数据库。

顶层模块：

1. 输入模块；
2. 思绪核心模块；
3. 记忆模块；
4. 输出模块；
5. 自循环模块；
6. 权限与安全模块。

核心运行关系：

```text
外部输入
  ↓
输入模块
  ↓
思绪核心：主程序
  ├─ 记忆模块
  ├─ 任务库 / 工作程序
  ├─ 自循环内部输入
  └─ 权限与安全
  ↓
输出模块
  ↓
语音 / 微信 / 文字 / 面板 / 文件成果
```

## 2. 总体架构原则

- 模块只通过稳定契约连接；
- 原始媒体不在模块事件中传递，只传媒体引用；
- 主程序负责交流、记忆使用、任务管理和最终判断；
- 工作程序负责实际工作，不直接与用户交流；
- 思绪核心拥有逻辑会话和任务状态真相；
- OpenClaw 是当前 Agent、文字会话、文字记忆后端，不是不可替换的领域核心；
- 权限按用户任务意图授权，不按工具调用机械询问；
- 自循环产生自主心理历程，但外部动作仍经过主程序与权限；
- 工作程序可以并行，但资源冲突必须由调度器协调；
- 用户输入始终优先于任务进度和自循环。

## 3. 输入模块

### 3.1 职责

输入模块负责：

- 接入语音、键盘文字、微信、摄像头及未来输入源；
- 将会话输入组装成完整消息；
- 定时维护环境状态；
- 保存媒体及其元数据；
- 提供输入、媒体和历史读取接口；
- 承载可插拔输入处理器；
- 向核心可靠交付完整消息。

输入模块不负责：

- 生成回复；
- 派发工作任务；
- 最终认定人物；
- 权限授权；
- 写入长期记忆。

### 3.2 两条输入路径

#### 完整消息输入

语音交付核心前必须完成：

- 切段；
- 唤醒判定；
- 最终语音转写；
- 声纹 / 主人身份线索；
- 原始音频媒体关联。

键盘文字交付前完成：

- 正文；
- 附件引用；
- 来源和时间。

微信交付前完成：

- 正文；
- 账号与发送者；
- 渠道与回复目标；
- 附件引用。

ASR、声纹等结果不作为多条独立输入推送；它们组装成一份完整消息。

#### 环境上下文

环境状态独立定时采集并缓存：

- 当前人物及在家 / 离家线索；
- 输入渠道和连续对话状态；
- 前台应用类别；
- 看视频、游戏、会议、勿扰状态；
- 音响、TTS、麦克风、摄像头可用性；
- 核心服务健康；
- 活动任务、待确认和高优先级结果摘要；
- 摄像头最新快照引用。

用户消息进入时直接读取最新缓存，不同步等待重新采集。

环境状态以结构化 `state_context` 形式提供给主程序，并明确标记：

> 状态仅供判断，不要求回复或复述。

工作程序默认不携带人物活动和家庭环境。工作进度返回主程序后，主程序可以按动作影响重新读取相关状态。

### 3.3 摄像头上下文

- 摄像头持续在内存中做基础检测与跟踪；
- 当前快照本身不默认进入模型；
- 主程序判断需要视觉信息时，主动调用视觉处理器；
- 视觉模型将最新帧转换成文字描述，最早在主程序第二轮成为工具结果；
- 自循环可以根据本地变化检测提前调用视觉模型，生成内部心理历程候选。

### 3.4 文字与媒体存储边界

文字正文、会话历史和文字记忆由 OpenClaw 当前后端保存。

输入模块只保存：

- OpenClaw 消息引用；
- 输入来源；
- 人物线索；
- 时间；
- 当前处理结果；
- 可信度；
- 音频、图像、视频和附件的关联。

媒体库：

- 保存原始音频、图片、视频和附件；
- 使用内容哈希作为媒体唯一身份；
- 同一内容只保存一次；
- 数据库仅保存媒体位置、哈希、引用、保留期限和处理元数据；
- 模块之间仅传媒体编号、哈希、类型和元数据；
- 读取内容时通过受控媒体流接口获取。

### 3.5 媒体持久化

语音：

- 只保存真正进入对话的语音；
- 背景人声、未唤醒语音不落盘；
- 用户标记“这句有问题”或开启诊断时，可以保存识别失败 / 误唤醒片段；
- 实时环形缓冲只在内存中存在。

摄像头：

- 默认不持续录像；
- 普通人物经过、普通背景画面不自动保存；
- 只保存用户明确要求的截图 / 短视频；
- 保存身份注册素材；
- 保存任务核验证据；
- 保存用户标记的问题片段。

### 3.6 保留与清理

采用分级保留：

- 文字消息引用和元数据长期保存；
- 原始媒体默认短期保存；
- 用户固定、长期记忆引用和任务证据可提升为长期保留；
- 每类媒体设置最长保留时间；
- 媒体库设置总容量上限；
- 任一清理条件满足时，删除最旧且没有长期引用的媒体；
- 最后一个长期引用解除后，媒体重新成为清理候选。

具体保留天数和容量属于部署配置。

媒体内容不额外加密，依赖 Windows 用户权限、目录 ACL 与磁盘安全。媒体接口仍必须鉴权，备份目标权限单独检查。

### 3.7 处理结果

- 每条输入只保留当前最新处理结果；
- 不保留处理版本历史；
- 原始媒体仍按保留策略存在；
- 当前结果保存来源和校准后的统一可信度；
- 后续自动结果可信度更高时可以覆盖人工纠正；
- 可信度接近时不自动覆盖，进入待复核；
- 各模型原始分数必须先通过各自校准器转换为统一可信度。

### 3.8 身份线索

输入模块只保存身份证据：

- 微信账号；
- 声纹候选及可信度；
- 人脸候选及可信度；
- Wi‑Fi 设备；
- 追踪编号。

输入模块不最终认定人物。核心统一身份解析能力综合判断当前人物，权限模块再独立决定授权。

### 3.9 状态新鲜度与冲突

每项环境状态必须包含：

- 值；
- 来源；
- 采集时间；
- 有效期限；
- 采集器健康；
- 可信度。

状态过期标记为 `stale`，采集异常标记为 `unknown`。两者不得继续作为当前事实，也不得阻塞用户消息。

多来源冲突时：

- 保留各来源观察；
- 状态聚合器根据新鲜度、校准可信度和来源适用能力计算；
- 无法稳定判断时输出 `uncertain`；
- 向主程序提供冲突摘要；
- 主程序不能任选一个候选当事实。

防止错误状态参与判断是输入模块最高优先级。

### 3.10 处理器扩展

所有输入处理器遵守统一接口。

处理器声明：

- 支持的输入类型；
- 输出字段；
- 处理器版本；
- 资源需求；
- 超时；
- 必要 / 增强类型；
- 备用链；
- 可信度校准器。

轻量处理器可进程内运行，重型 / GPU 处理器可作为独立服务。输入模块不依赖其部署形态。

必要处理器失败时先使用备用链；全部失败才判定输入失败。增强处理器失败只记录缺失和原因，不阻塞消息。

### 3.11 消息交付

- 每条完整消息有全局唯一输入编号；
- 采用“至少交付一次”；
- 核心按输入编号幂等去重；
- 默认最多重试 3 次；
- 重试采用指数退避；
- 模块重启后继续未完成交付；
- 超过上限后进入失败队列；
- 失败队列保留输入编号、失败阶段、原因、尝试次数和最后时间；
- 面板展示告警；
- 人工重放仍使用同一输入编号。

## 4. 思绪核心模块

### 4.1 主程序与工作程序

主程序负责：

- 与用户交流；
- 使用相关记忆；
- 读取结构化环境状态；
- 调用低复杂度只读能力；
- 创建和管理工作任务；
- 接收聚合后的任务进度；
- 判断工作是否完成；
- 生成所有用户可见语义内容；
- 选择说话、沉默、派活或追问。

主程序不直接：

- 执行代码或命令；
- 写文件、编辑内容；
- 下载、安装、删除；
- 控制外部程序与设备；
- 做多步骤搜索。

工作程序负责实际工作：

- 代码；
- 搜索；
- 编辑；
- 命令执行；
- 文件与文档生成；
- 外部程序和设备操作；
- 产生结构化进度、成果和证据。

工作程序可以是：

- Agent 框架；
- 一次模型调用；
- Python / PowerShell 等确定性程序；
- 远程服务。

### 4.2 Agent 运行接口

核心依赖统一 Agent 运行接口，不绑定 OpenClaw。

当前可以使用 OpenClaw 适配器，未来可以增加：

- Cursor / Claude Code 等 Agent 适配器；
- 其它 Agent 框架；
- 直接模型 API。

适配器负责把模型流式输出、工具请求、取消、错误和会话转换成思绪内部协议。

思绪核心拥有逻辑会话编号、休眠状态和换新时机。当前适配器将逻辑会话映射到 OpenClaw session，文字正文由 OpenClaw 保存。

### 4.3 主线生命周期

主人语音和主人微信共用长期主线。

休眠由多信号状态机判断：

- 电脑锁定、明确离家属于强信号；
- 摄像头无明显变化；
- 长期无有效人声；
- 长期无消息交互；
- 人物和环境状态；
- 任务、待确认和未交付结果。

无人活动可信度达到条件后进入休眠。新消息、人声和明显画面变化会降低或清空无人活动状态。

运行任务、待确认动作或未交付结果存在时，不得直接换新。

休眠流程：

1. 总结当前会话；
2. 向记忆模块提交长期内容；
3. 压缩自主心理历程；
4. 创建新的主线会话；
5. 保留逻辑主线连续性。

### 4.4 主程序上下文

每轮动态编译。

固定部分：

- 人格；
- 表达原则；
- 核心事件协议；
- 本轮允许事件 schema。

动态部分：

- 当前完整消息；
- 相关会话历史；
- 限量相关记忆包；
- 结构化环境状态；
- 当前任务摘要；
- 本轮允许的只读能力和任务管理能力。

不相关工具、技能、记忆、家庭状态和工作细节不进入上下文。

模型选择由独立模型策略模块负责：

- 默认优先 GLM FlashX；
- 主程序、工作程序、视觉、记忆维护各有独立策略；
- 能力可声明最低模型能力、上下文和成本上限；
- 各角色独立 fallback；
- 模型选择进入审计。

### 4.5 主程序事件流

主程序输出独立完整 JSON 事件：

- 回话片段；
- 保持沉默；
- 创建工作任务；
- 任务控制；
- 低复杂度只读调用；
- 输出请求；
- 记忆请求；
- 本轮完成。

事件逐条校验：

- 未知事件、非法 JSON 或缺少字段不执行；
- 允许模型根据校验错误修复一次；
- 第二次仍失败，本轮未提交副作用全部作废；
- 不从自由文本猜测控制事件；
- 返回明确降级回复。

提交规则：

- 普通回话片段可以流式输出；
- 任务、工具、控制和外部输出事件先进入本轮暂存区；
- 收到“本轮完成”后原子提交副作用；
- 任务持久化成功后才能确认“已接单 / 已开始”；
- 中途失败时未提交动作全部丢弃。

### 4.6 主程序直读能力

主程序只允许直接调用：

- 记忆查询；
- 环境与设备状态读取；
- 任务状态、进度和结果查询；
- 任务暂停、中断和优先级调整；
- 输出请求；
- 其它已登记的低复杂度只读能力。

低复杂度直读能力必须由能力目录声明，并同时满足：

- 无副作用；
- 单次查询；
- 低延迟；
- 返回量有限；
- 不需要多步骤推理；
- 有明确超时和失败状态。

其它只读工作也交给工作程序。

### 4.7 工作任务单

主程序向工作程序提供：

- 目标；
- 约束；
- 资料引用；
- 权限范围；
- 优先级；
- 成功标准；
- 结果交付要求；
- 任务要求修订号。

主程序不提前规划完整执行步骤。工作程序自行规划。固定流程和高风险流程可引用系统模板。

工作程序只能接收任务范围上下文，不直接读取完整主线历史和长期记忆。需要更多背景时提交上下文请求，由主程序补充。

### 4.8 工作程序统一适配接口

所有工作程序必须支持统一接口：

- 启动；
- 进度事件；
- 子任务请求；
- 暂停；
- 恢复；
- 取消；
- 任务修订确认；
- 结果；
- 错误；
- 资源声明；
- 权限请求；
- 健康状态。

不同 Agent、模型和程序的差异由适配器内部处理。

每个任务使用独立 Agent 会话。执行进程和模型连接可以复用，但任务上下文不跨任务继承。

同一任务的修改、暂停和恢复继续使用该任务会话。

任务结束后：

- 在配置期限内保留详细工作会话、事件和证据；
- 到期删除详细会话；
- 长期保留任务摘要、关键证据、成果引用和正式记忆；
- 争议或安全任务可延长保留。

### 4.9 任务状态真相

思绪核心独立持久化：

- 任务状态；
- 要求修订；
- 父子任务；
- 资源；
- 进度；
- 权限；
- 成果；
- 错误；
- 任务事件。

OpenClaw、Cursor、Claude Code 等只负责运行，不拥有任务状态真相。

### 4.10 工作进度

工作程序细粒度事件完整进入任务事件流。

进度聚合器根据能力目录中的复杂度和进度策略决定是否形成进度包：

- 简单任务：无中间进度，只返回结果或异常；
- 普通任务：少量关键阶段；
- 长任务 / 高风险任务：低频里程碑与累计进度。

聚合后的进度包交给主程序。主程序决定：

- 对用户说话；
- 只更新上下文；
- 明确输出“保持沉默”。

### 4.11 子任务

工作程序不能直接创建或控制其它工作程序。

它只能提交子任务请求：

- 目标；
- 原因；
- 依赖成果；
- 建议优先级；
- 权限需求。

主程序决定是否创建。

批准后建立父子任务关系：

- 子任务成果进入成果库；
- 调度器将成果引用交回父任务；
- 工作程序之间不直接聊天；
- 主程序可以查看依赖和阻塞关系。

### 4.12 任务修改与打断

用户修改任务时保持同一个任务编号。

- 任务要求原地更新；
- 内部要求修订号递增；
- 工作程序收到变更后确认并重新规划；
- 修改前步骤返回的结果标记为旧修订；
- 旧修订结果可作为证据，但不能更新当前状态。

用户输入可以取消主程序正在处理的低优先级进度或自循环模型调用：

- 停止对外输出；
- 取消剩余模型生成；
- 未提交动作作废；
- 已提交任务不自动撤销；
- 用户输入立即进入最高优先级队列。

### 4.13 并发、资源与优先级

工作程序默认并行。

启动同时受三层限制：

1. 可配置的全局安全上限；
2. 每类能力最大并发；
3. 实际资源声明和可用状态。

能力声明资源：

- CPU / 内存；
- GPU 与显存；
- 网络；
- 浏览器会话；
- 摄像头读 / 云台独占；
- 麦克风 / 音响；
- 前台桌面；
- 文件 / 目录锁；
- 其它设备。

资源声明包含共享 / 独占、最大数量、是否支持暂停释放、是否依赖桌面会话。

互不冲突的工作程序不互相影响。发生资源冲突时：

- 高优先级任务请求抢占；
- 低优任务在安全检查点暂停；
- 保存进度并释放资源；
- 高优任务执行；
- 资源释放后恢复低优任务；
- 不强杀正在执行的步骤。

### 4.14 权限与外部 Agent

使用双层防护：

1. 思绪权限模块做最终业务授权；
2. 外部 Agent 原生权限和沙箱做第二层保护。

两层都通过才能执行。

### 4.15 工作重试

能力目录声明：

- 可重试错误；
- 最大次数；
- 退避；
- 备用路径。

工作程序在范围内自动重试。

权限拒绝、参数错误、用户取消和确定性失败不得盲重试。

超出边界后交给主程序决定：

- 换方案；
- 请求更多信息；
- 派子任务；
- 报告失败。

### 4.16 工作完成判断

工作程序返回：

- 结果摘要；
- 成果引用；
- 关键步骤；
- 外部状态证据；
- 错误与未完成项；
- 证据采集时间；
- 任务修订号。

主程序判断：

- 已完成；
- 未完成；
- 需要验证；
- 继续派活；
- 无法确认。

主程序可调用低复杂度只读工具复核。证据不足时只能说“未核实”，不得宣称完成。

### 4.17 主程序事件优先级

从高到低：

1. 当前用户输入与确认；
2. 高风险权限和关键异常；
3. 任务最终结果与需要用户回答的事项；
4. 节流后的普通进度；
5. 自循环心理历程。

低优事件可合并；自循环和普通进度不得抢占用户对话；主程序不并行产生冲突决策。

## 5. 记忆模块

### 5.1 总体结构

思绪只有一份整体记忆：

- 一套长期记忆；
- 一套索引；
- 一套可信度；
- 一套遗忘规则；
- 一个记忆维护工作程序。

不建立主人记忆、老婆记忆、工作程序记忆等独立记忆库。

内容可以标注涉及谁、来自谁，但只是语义标签。

敏感内容是否可向当前交流对象披露，由权限与输出模块处理，不通过拆分记忆解决。

### 5.2 OpenClaw 适配

思绪记忆模块定义：

- 类型；
- 来源；
- 可信度；
- 冲突；
- 学习；
- 遗忘；
- 检索；
- 媒体关系。

OpenClaw 作为当前文字会话、文字记忆、索引和检索后端，通过适配器接入。

未来更换后端不改变记忆模块契约。

### 5.3 记忆类型

- 当前会话摘要；
- 人物画像；
- 事件经历；
- 长期事实与决定；
- 工作经验；
- 多媒体关联；
- 原始证据引用。

### 5.4 自动学习

所有类型记忆都允许自动写入。

条件：

- 记忆模块判断可信度达到阈值；
- 来源合法；
- 证据可追溯；
- 通过冲突规则。

不要求逐条人工确认。

### 5.5 更新与冲突

记忆直接覆盖当前值：

- 不保留旧值；
- 不保留变更历史；
- 不提供一键回滚；
- 当前值保留当前来源与可信度。

冲突规则：

- 用户明确纠正直接覆盖；
- 其它情况只有新证据可信度明显更高才覆盖；
- 可信度接近时标记不确定并等待更多证据；
- 重要冲突或影响当前决策时，记忆模块向主程序提交澄清请求；
- 主程序选择合适时机询问用户。

### 5.6 检索与主程序注入

每轮主程序自动获得限量相关记忆包。

检索依据：

- 当前消息；
- 当前人物；
- 会话主题；
- 环境状态；
- 当前任务。

记忆包有数量和 token 上限。

主程序需要更多时，可以按人物、主题、时间、事件、任务或媒体关系主动查询。

### 5.7 视觉记忆

重要视觉经历保存：

- 文字事实 / 事件摘要；
- 原始图片或短视频引用；
- 本地视觉特征 / 向量；
- 来源、时间和可信度。

文字用于语义检索，本地特征用于人物、场景、物体和相似性检索，需要时可回看媒体证据。

### 5.8 保留与遗忘

记忆等级：

- 永久；
- 长期；
- 自适应；
- 临时。

规则：

- 核心身份事实和明确长期保留内容不自动降低可信度；
- 多次独立出现、反复使用会提高重要度和保留期限；
- 偏好与习惯长期不再出现时降低可信度；
- 普通事件可压缩或过期；
- 用户明确纠正可以覆盖永久记忆。

专门的记忆维护工作程序定期评估重要度、重复次数、最近使用、类型和证据。

### 5.9 经验进化

记忆模块发现重复经验适合代码化时：

1. 生成能力提案；
2. 在同一机器的隔离目录 / 工作区实现；
3. 使用模拟数据或受控真实数据测试；
4. 测试通过后进入“待批准”；
5. 用户批准后注册进能力目录；
6. 成为正式可调用能力。

产物可能是：

- 确定性程序；
- Skill；
- 工作程序适配器；
- 输入处理器；
- 只读能力；
- 工作流程模板。

未批准前不得出现在正式能力目录。

## 6. 输出模块

### 6.1 模块边界

工作程序直接执行实际动作：

- 写文件；
- 生成文档；
- 下载和安装；
- 打开 / 关闭程序；
- 控制摄像头与设备；
- 调用外部服务。

输出模块不代替工作程序执行。

输出模块负责：

- 用户可见内容呈现；
- 渠道投递；
- 语音表现；
- 成果交付展示；
- 静默；
- 去重；
- 发送和送达状态；
- 渠道失败回退。

### 6.2 内容归属

普通回复、进度、最终结果和失败说明由主程序统一生成。

工作程序不能直接给用户发消息。

确定性系统状态可以使用固定模板，例如：

- 已接单；
- 等待确认；
- 发送失败；
- 已取消。

### 6.3 结构化表达

主程序提供：

- 文字；
- 语气；
- 情绪强度；
- 语速；
- 停顿；
- 重要度；
- 是否允许打断；
- 是否适合朗读。

输出模块将表达信息映射为 TTS 参数、分句和呈现方式，不重新改写语义。

### 6.4 渠道策略

主程序提供：

- 目标人物；
- 首选渠道；
- 重要度；
- 是否允许延迟；
- 是否必须被看到；
- 是否适合朗读。

输出模块结合：

- 本轮输入来源；
- 人物在线 / 在家状态；
- 渠道健康；
- 影音 / 游戏 / 勿扰状态；
- 回退规则；

决定语音、微信、文字、托盘、面板等最终渠道。

输出状态：

- 等待发送；
- 已发送；
- 已送达；
- 失败；
- 已回退。

每条输出有唯一编号用于去重。

### 6.5 语音流式播放

- 第一条完整句子或安全语义片段到达后立即合成；
- 后续句子继续生成、合成和排队；
- 不等待整段回复；
- 不播放半句话、半个 JSON 或控制内容；
- 每个片段继承语气、语速和可打断属性；
- 微信与面板可以持续显示完整文本。

### 6.6 用户插话

用户插话时：

- 立即停止当前音频；
- 取消未播放片段；
- 取消本轮剩余主程序生成；
- 未提交动作作废；
- 已提交任务不自动撤销；
- 新输入进入主程序最高优先级；
- 面板可以保留已生成和已说出的部分。

## 7. 自循环模块

### 7.1 运行形态

采用事件驱动 + 低频周期复盘。

事件先形成候选：

- 环境变化；
- 任务完成；
- 提醒；
- 长期未结事项；
- 视觉变化；
- 记忆变化。

候选不会立即调用模型或输出。

自循环按低频节奏聚合候选，统一调用模型思考。没有足够价值时保持沉默。

紧急事件可以提前，但仍经过主程序、权限和输出模块。

### 7.2 心理历程状态

自循环维护独立短期状态：

- 近期考虑话题；
- 已沉默候选；
- 话题冷却；
- 最近主动表达；
- 主动工作记录；
- 未解决想法；
- 等待条件；
- 当前关注度；
- 新鲜度。

该状态会定期压缩和过期，不等于长期记忆。

### 7.3 主动工作范围

可以自动执行：

- 记忆维护；
- 索引更新；
- 状态检查；
- 信息预取；
- 内部数据整理；
- 预计算；
- 能力提案的隔离实现与测试。

不能直接执行外部副作用：

- 发微信；
- 控制外部程序；
- 控制设备；
- 写外部文件；
- 下载、安装、删除。

外部动作只能形成主动任务候选，交给主程序与权限流程。

### 7.4 主动表达

候选评估：

- 对用户的价值；
- 紧急度；
- 新鲜度；
- 与当前活动关系；
- 最近是否讨论过；
- 打扰成本；
- 是否可以延迟到下一次用户交流。

约束：

- 同话题冷却；
- 同类事件合并；
- 每日主动表达预算；
- 影音 / 游戏 / 勿扰抑制；
- 没有价值时必须沉默。

### 7.5 视觉

- 本地代码持续做画面变化、人物和目标检测；
- 无明显变化时不调用视觉模型；
- 有意义变化形成候选后，才获取快照并调用视觉模型；
- 视觉模型产生带媒体来源的文字描述；
- 结果进入心理历程候选；
- 媒体保存遵守输入模块规则；
- 视觉调用受主动预算限制。

### 7.6 心理历程进入主线

心理历程写入主人主线历史，使用：

```text
role: internal_thought
source: self_loop
```

必须明确：

- 不是用户消息；
- 不可作为用户原话引用。

当前主线保留完整心理历程。

休眠总结换新时压缩为：

- 当前关注点；
- 未解决想法；
- 已沉默候选；
- 主动表达记录；
- 等待条件。

详细心理历程随旧会话归档；稳定认识单独提交记忆候选。

## 8. 权限与安全模块

### 8.1 授权哲学

按用户任务意图授权，不按每个工具调用询问。

用户明确任务默认授权：

- 完成目标所合理需要；
- 同一目的；
- 同一对象范围；
- 同一风险范围；
- 可逆步骤。

只有以下情况重新评估：

- 范围扩大；
- 派生高影响动作；
- 不可逆；
- 公开外发或代表用户表达；
- 敏感信息；
- 自循环主动任务；
- 来源不可信或对象含糊。

### 8.2 二次确认范围

即使主人明确下令仍必须二次确认：

- 格式化、破坏系统、不可恢复系统修改；
- 永久删除重要数据；
- 财务交易；
- 公开发言或代表用户发送重要内容；
- 修改账户和权限；
- 读取并外发密码、密钥、令牌等敏感凭据。

以下不因类别自动二次确认：

- 普通软件安装；
- 可信安装包运行；
- 关机 / 重启；
- 结束普通程序；
- 普通文件移动到回收站；
- 任务范围内合理步骤。

### 8.3 角色权限

基础角色：

- 主人；
- 可信家人；
- 普通家人 / 来访者；
- 系统自循环。

未来可增加儿童、临时访客、远程代理。

微信账号、声纹、人脸等只绑定角色。能力目录按角色声明：

- 允许；
- 只读；
- 需确认；
- 禁止；
- 是否可创建主动任务；
- 敏感输出范围。

身份识别不能绕过权限模块。

### 8.4 授权范围

一次确认默认覆盖当前任务内：

- 相同目的；
- 相同对象；
- 相同风险范围；
- 后续步骤；
- 子任务。

任务修订扩大范围或提高风险时重新评估。

用户明确“以后都允许”可创建长期授权规则。

长期规则绑定：

- 角色；
- 能力；
- 对象范围；
- 限制条件；
- 有效期。

### 8.5 跨渠道确认

待确认动作有唯一待办编号。

语音、微信和面板读取同一待办。

任何能可靠识别为同一授权角色的可信渠道均可确认。

确认后其它渠道同步状态。

不依赖最后说话渠道或模糊上下文。

### 8.6 自然语言确认

主程序结合唯一待办，将用户回答解释为：

- 同意；
- 拒绝；
- 延后；
- 不确定。

权限模块只接受结构化决定，并继续验证：

- 人物角色；
- 待办编号；
- 任务范围；
- 风险范围；
- 有效期。

含糊时主程序追问，不要求固定口令。

### 8.7 权限检查位置

- 主程序直读工具；
- 主程序创建工作任务；
- 工作程序每个外部动作；
- 自循环主动任务；
- 输出模块的公开外发与敏感交付；
- 自动生成能力的正式注册。

工作程序还必须通过外部 Agent 自带权限和沙箱。

- 主动表达评分与预算默认值；
- 权限角色的初始能力矩阵；
- 输出送达和回退策略；
- TTS 表达参数与音色能力；
- OpenClaw 适配和迁移方案；
- 新架构与当前运行系统的分阶段迁移计划。

## 11. 验收方向

架构实现后至少应满足：

- 普通消息不因环境采集阻塞；
- 过期状态不会作为当前事实；
- 语音、微信和文字进入同一主程序逻辑；
- 主程序不能直接执行重型副作用动作；
- 多个工作程序可在资源允许时并行；
- 用户修改任务后旧修订结果不能污染当前状态；
- 普通小任务不频繁汇报进度；
- 用户输入可以抢占自循环和普通进度处理；
- 工作完成结论有结构化证据；
- 输出内容只由主程序组织；
- 语音可按句流式播放并被用户打断；
- 自循环没有价值时保持沉默；
- 普通任务不逐工具询问权限；
- 高影响确认可跨可信渠道完成；
- 记忆可自动学习、冲突澄清、按重要度维护；
- 自动生成的新能力测试通过且经用户批准后才可注册。
