## 0. 结论速览

**根因（按影响大小排序）**

1. **注册向量和现在的音频链路不一致**（主因）。声纹库是 09-30 23:16 在 **speex AEC + 预处理降噪开启**的链路上录的；00:51 起 AEC 关了，库没重录。离线实验：同一晚、同一支麦、**不过 AEC** 的主人录音 `mic_check.wav` 拿来当参照，今晚主人喊「管家」的平均分从 **0.37 → 0.51**，非主人/噪声只从 0.27 → 0.32，主人与其他的差距翻倍（0.10 → 0.19）。而现在的库连同一晚的主人原声都只给 **0.61**。
2. **注册算法有 bug：不是平均，是「越晚越重」的指数加权**。`SpeakerGate.enroll()` 每加一段就 `normalize(旧向量 + 新向量)`，最后一段占一半权重，前面的按约 0.5~0.6 的倍数衰减。24 秒、十来段的注册，实际只由最后两三段决定；第二轮又会压过第一轮。
3. **片段太短，而且被音箱 DSP 噪声门切得更短**。P2 上了唤醒词后，主人最常说的是单独一句「管家」，VAD 段 0.5~1.0 秒，raw 里 **6%~60% 是数字零**（噪声门把弱音、尾音整个抹掉），真正有声的只剩 0.5~0.9 秒。CAM++ 在这种长度上分数天然塌陷：主人自己的录音截 0.5 秒对库平均 0.26，1 秒 0.34，≥1.5 秒约 0.40。
4. **门禁设计把最难的句子放在最严的位置**。`decide()` 先过声纹、再看唤醒词，两道门是「与」关系；最短、最难认的「管家」偏偏要先过声纹硬门槛。唤醒词已经能挡住大部分误触发，声纹再硬拦就是重复把关、只增加漏拒。
5. 次要：**换模型不是解法**。ERes2NetV2 把所有人的分数整体抬高约 0.1，主人与其他的差距（≈0.10~0.13）不比 CAM++（0.10，换参照后 0.19）好，且模型大 2.5 倍。
6. 已排除：3 倍软件增益（tanh 软限幅；增益前后向量余弦 0.993，对分数影响 ≤0.02）；onnxruntime 版本（注册和使用都是 1.30，09-29 起就装着）。

- **今晚主人和非主人分不开**：主人喊唤醒词最高 0.39，背景/其他句子最高 0.49、碎音最高 0.53，区间完全重叠。门槛 0.45 时，6 次唤醒尝试全部被拒，39 句有内容的话被声纹拒了 32 句；用户 23:08:42 把门槛调到 0.20 后才第一次唤醒成功（「管家」0.39）。0.20 下声纹基本只拦得住数字静音。

## 1. 声纹流程现状

### 1.1 用什么模型
- `src/guanjia/speaker.py`：sherpa-onnx `SpeakerEmbeddingExtractor`，默认 `campplus` = `models/3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`（192 维），对应库 `data/speakers.npz`。环境变量 `GUANJIA_SPK_MODEL=eres2netv2` 可切 ERes2NetV2，库为 `speakers.eres2netv2.npz`。
- 运行日志 22:45:53 启动行确认：`speakers=['我'](3dspeaker_speech_campplus_sv_zh-cn_16k-common), gate=enforce@0.45, wake=管家(required=True) followup=20s, mic_gain=3.0, aec=off`。
- 进程里先载 onnxruntime 1.30（`ort_preload.py`），sherpa-onnx 1.13.8。

### 1.2 片段怎么来
`voice.py::_frontend_step`（329~370 行）：

```
麦克风 16k（MME，pick_stream_rate 选 16000）
  → AEC（现在关）→ Downsampler（16k 时直通）
  → apply_mic_gain：np.tanh(x × 3.0) 软限幅
  → Silero VAD（threshold 0.5、min_silence 0.8s、min_speech 0.25s）
  → 一句话说完弹出一段 seg.samples
  → < 0.4s 丢弃；SenseVoice 整段识别；文本为空丢弃
  → gate.identify(seg.samples)  ← 整段送声纹
```

- **长度**：整句 VAD 段，不截不拼。今晚 67 段里 0.4~21 秒都有；喊「管家」的段 0.5~1.0 秒。
- **是否含静音/噪声**：含。段内没有任何去静音；音箱 DSP 噪声门把低电平直接置零，raw 段里数字零占比：「管家」6%~42%、「管他」59%、纯噪声段「嗯」84%。长段（10~21 秒、识别只出「我/就/哎了」）基本是背景声。
- **是否用增益后的音频**：是。送声纹的是 `tanh(3x)` 之后的 16k 信号（`_dump_segment` 落的 `_proc.wav` 就是它，离线复算与线上分数误差 ≤0.01 证实）。

### 1.3 怎么打分、门槛多少
- `embed()`：整段提一个向量并 L2 归一；`identify()`：与库里每个人的向量做点积（= 余弦相似度），取最大；`< threshold` 判为不是。库里只有一个人「我」，所以就是「这句和『我』的余弦」。
- 门槛来自 `data/voice-settings.json` 的 `spk_threshold`（面板可调、2 秒内热生效）。`settings.py` 默认 0.45；**现在文件里是 0.20**（23:08:42 用户在面板改的）。历史：0.50 → 0.40（09-30 23:38）→ 0.30（23:55）→ P2 默认 0.45（10-10 22:42）→ 0.20。
- `wake.py::decide()` 的顺序：碎音过滤 → **声纹 < 门槛直接 rejected** → 唤醒词 / 免喊窗口。含唤醒词的话也要先过声纹。

### 1.4 注册向量和现在的链路一致吗：**不一致**
| 项 | 注册时（09-30 23:16） | 现在 |
|---|---|---|
| 设备 / 采样率 | EDIFIER Halo 麦，16k | 同 |
| speex AEC + 预处理降噪 | **开**（`make_aec(sr)` 第 4 个参数 True = 预处理） | **关**（10-01 00:51:36 起） |
| 软件增益 | 无（记录：当时还没加） | ×3 tanh |
| 内容 | 对着麦连续说 12 秒 × 2 轮 | 多为「管家」+ 一句短指令 |
| 距离 / 语气 | 近、平静 | 不固定 |
| 聚合方式 | 有 bug 的累加归一（见 4.2） | — |

`enroll.py` 现在的 `to_16k_like_daemon()` 会跟随当前 `AEC_ENABLED/MIC_GAIN`，所以**现在重录**就是一致的链路；但它的修改时间是 10-01 00:50，现有库是之前录的。

## 4. 根因判断

### 4.1 注册与使用链路不一致（主因，证据强）
- 注册在 AEC + speex 预处理（降噪）上，使用在无 AEC 上；分数随之从 0.60 跌到 0.47，再叠加短句跌到 0.33。
- 离线：换成无 AEC 的参照，主人 +0.14、差距 ×2。

### 4.2 注册样本太少、太单一，而且聚合算法错了（证据：代码）
`speaker.py` 83~90 行：

```python
v = self.embed(samples, sr)
if name in self._db:
    v = self._db[name] + v
    v = v / (np.linalg.norm(v) + 1e-9)
```

库里只存一个**已归一化**的向量，每加一段就和新段等权相加再归一：第 n 段权重 ≈ 1/2，第 n−1 段 ≈ 1/4……（段间相似度约 0.5 时衰减系数约 0.58）。所以：
- 两轮 × 12 秒切出的十来段，实际只由最后两三段决定；
- 文档里建议的「近/远/带情绪各录一次叠加」**做不到**，越后录的越覆盖前面的；
- 样本全是近距离、平静、连续朗读，和日常「隔着一段距离喊一声管家」差别很大。
- 现有库对同一晚的主人原声只有 0.61，也说明这个向量代表性很差。

### 4.3 片段太短 + 噪声门截断（证据强）
唤醒词让最常见的输入变成 0.5~1 秒的「管家」，噪声门再砍掉 20%~60%。CAM++ 在 < 1 秒上同一人的分数只有 0.26~0.40，波动大。

### 4.4 门禁设计（证据：代码 + 统计）
`decide()` 把声纹放在唤醒词之前、硬拒；唤醒词句天然最短。另外，免喊窗口里的后续指令同样要过声纹硬门槛。

### 4.5 模型选择、打分方法（次要）
- 模型：ERes2NetV2 不比 CAM++ 好，不是根因。
- 打分：单一质心 + 原始余弦 + 全长度统一门槛，对短句没有任何补偿；也没有用「同一轮里唤醒词 + 指令」的累积证据。这些是优化项，不是主因。

### 4.6 已排除
- 3 倍增益：影响 ≤0.02。
- onnxruntime 版本：注册、使用都是 1.30。（但**离线评估必须同样预载 1.30**，否则偏差可到 0.08，`seg_eval.py` 以后做对比要注意。）

## 5. 改进方案

### 先定位：二代里声纹该干什么
唤醒词已经是第一道门，挡掉了背景闲聊、电视和误触发的大头。声纹再做「每句硬拦」，收益小、代价是主人被拒。建议声纹改做三件事：

1. **软门禁**：带唤醒词的话**不因声纹被拒**；声纹只在没有唤醒词的场合（免喊窗口里的后续话）当门槛，防止电视/旁人接话。
2. **身份标签**：给每句标「主人 / 家人 / 不认识」，供权限分级用（例如 L2/L3 操作要求「主人且分数高」，否则走微信审批）。现在库里只有「我」，要区分家人得先给家人注册。
3. **记录**：分数写进 utterances.jsonl，作为以后校准的数据。

代码层面是 `decide()` 的顺序：命中唤醒词时把声纹结果降为「标签 + 日志」，只在 `hit is None and in_window` 分支用门槛。改动约十几行 + 单测。

### 方案 A：面板引导重新注册（推荐，主要收益）
- **做法**
  - 面板加「声纹注册」页：引导录 8~12 段，每段 3~5 秒，分三组提示词：近处平常说、2~3 米外正常说、带情绪/大声/随口说；内容包含「管家，……」这类真实指令。
  - **走守护进程同一条链**：不要另开录音程序，而是让守护进程进入「注册模式」，把接下来 N 句 VAD 段（AEC 关、×3 增益、同一 VAD）直接拿来注册。这样自动和日常链路一致，以后链路再变也只需在面板重录。
  - 修注册算法：库里**保存每段的向量**（形状 `[N, 192]`），打分用「对所有样本向量的平均余弦」或「top-k 平均」，不再只存一个累加向量；按名字分组，家人也能注册。
  - 质量检查：每段去零后有效语音 ≥1.5 秒、峰值电平合格、数字零占比 < 50%，不合格让用户重说；结束时留一段不参与注册来自测，面板显示分数。
  - 旧库备份成 `speakers.campp.pre-reenroll.npz`，可回滚。
- **预期效果**：按离线实验，主人分数约 +0.10~0.15（≈0.37 → 0.50），主人与背景的差距约翻倍；多距离多语气的样本应能进一步改善远距离和情绪化的话（离线数据不足以量化）。短句（< 1 秒）依然偏低，所以仍要配合上面的软门禁。
- **工作量**：1~1.5 天（control.py 接口 + panel.html 页面 + 库格式迁移 + 单测）。

### 方案 B：自适应更新（在 A 之后做）
- **做法**
  - 候选条件（全满足）：命中唤醒词；分数 ≥ 主人高置信线（A 之后按主人分布的中位数定，例如 0.55）；去零后有效语音 ≥1.5 秒；当时没在播 TTS（`state != SPEAKING`，没触发打断），避免把自己的回声和 SCV 声音学进去；这一轮没有被用户否认（后续没有「不是我/停」）。
  - **防污染**
    - 注册样本是「锚」，永不被自动改；自适应样本进单独的池（最多 30 条，先进先出）。
    - 候选必须**对锚**达标，而不是对「锚+池」，防止越学越偏。
    - 打分 = max(对锚, 对池)，或者锚权重固定 ≥0.5。
    - 每天最多加 5 条；面板列出最近加入的样本，可以试听和一键删除，也可以「清空池」。
    - 每周离线回放一次：池里的样本对锚平均分持续下降就自动冻结、提醒重录。
- **预期效果**：跟住季节、感冒、换座位、换麦等慢变化；每次链路改动后不必马上重录。对今天这种「锚本身就错了」的情况没用，所以要排在 A 后面。
- **工作量**：0.5~1 天。

### 方案 C：分数校准 / 按句长调门槛 / 多模型融合（有数据以后做）
- **做法**
  - **整轮累积证据**：同一轮里「管家」+ 紧接的指令段拼起来（或向量平均）再打分，让 0.5 秒的唤醒词借后面那句的长度。实现简单，收益可能比单纯调门槛大。
  - **按句长分档门槛**：< 1 秒不下结论（标「不确定」，不拦）；1~2 秒、≥2 秒各一档，用面板标注数据定。
  - **分数归一化（AS-norm）**：用日志里积累的大量「非主人/噪声」段向量做对照集，把原始余弦换成相对分，跨距离、跨长度更稳定。
  - **多模型融合**：CAM++ 与 ERes2NetV2 各自归一化后取平均。本次离线两者区分度差不多、相关性高，预计收益有限；ERes2NetV2 大 2.5 倍、更慢，在前端线程同步跑（`voice.py` 末尾 P2-11 注释）会拖打断判定。**不推荐优先做**。
  - 面板加「这句是我 / 不是我」按钮，攒标注数据，没有它校准无从谈起。
- **预期效果**：累积证据 + 句长分档能直接缓解短句问题；AS-norm 让门槛跨场景更稳定；融合预计只有小幅提升。
- **工作量**：累积证据 + 分档约 0.5 天；AS-norm 约 0.5 天；融合约 1 天（主要是性能）。

### 推荐路线
1. **当天**：改 `decide()`，唤醒词句不被声纹拒，声纹只管免喊窗口；面板的 `spk_threshold` 改回有意义的值（例如 0.35，只作用于免喊窗口）。用户立刻不再被拒，背景误触发由唤醒词挡。
2. **本周**：方案 A（面板引导重录 + 修注册算法 + 质量检查）。
3. **之后**：方案 B（锚 + 自适应池），再按需加方案 C 的整轮累积和句长分档。家人有需要时在 A 的页面注册，声纹才真正承担「区分主人和家人」。

## 6. 顺带发现的代码问题
- `speaker.py::resolve_model` 的 docstring 写「再缺省用 ERes2NetV2」，实际默认 `campplus`；模块 docstring 还写「阈值先取 0.5」，与现行 0.45/0.20 不符。注释过时。
- `SpeakerGate(threshold=0.5)` 构造默认值和 `Settings.spk_threshold=0.45` 两处各写一个默认，容易不一致。
- `enroll()` 的累加归一 bug（见 4.2），而且每加一段就 `_save()` 一次。
- `identify()` 对整段（含噪声门零）提向量；如果以后改成去零或拼接，注册和使用两侧必须一起改。
- `enroll.py` 的提示语「GUANJIA_SPK_MODEL=campplus 可切回 CAM++」是 ERes2NetV2 实验时期遗留，现在默认已是 CAM++。
